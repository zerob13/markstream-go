# Contributing

Use Go 1.27.3+, matching `go.mod`. Keep the MyGo dependency pinned; update it in an explicit change with parser, native UI and demo checks.

1. Run `go mod download`.
2. Make focused changes with tests for observable behavior.
3. Format with `gofmt` and run `go vet ./...`.
4. Run `go test ./...` and `go test -race ./...`.
5. Run `go run ./examples/demo -smoke` and inspect a native snapshot for UI changes.
6. Use a Conventional Commit such as `feat:`, `fix:`, `test:` or `docs:`.

Keep background work outside UI callbacks. `Session` is concurrent; MyGo view building and `Document` mutation are single-goroutine operations. Never retain an `ui.Element` across frames; retain a `ui.Handle` or application data instead.

Performance changes should include a reproducible benchmark, source size, chunk size and native frame validation. Do not replace a parser with approximate delimiter matching or claim a custom hook is a bundled renderer. Document compatibility limits in `docs/parity.md`.

Generated binaries, coverage and development artifacts belong under `artifacts/` and stay untracked. The documentation screenshots are intentionally tracked and generated by the demo's native software renderer.
